## 幻覚・前提ミス

- 使用するAPI・メソッドが対象ライブラリの該当バージョンに存在することを確認する
- 既存コードベースの規約に合わせる。プロジェクト内に前例のないパターンを持ち込まない
- 実装前に既存の類似処理を検索し、同じ方針で書く

## フォールバック濫用

- 必須データに `?? 'unknown'` や `|| 'default'` を使わない。エラーとして検出する
- `catch { return ''; }` でエラーを握りつぶさない。上位に伝播させる
- 全呼び出し元が省略するデフォルト引数は削除し、必須にする
- `options?.x ?? fallback` で値を渡す経路がない場合、経路を作る

## スコープクリープ

- 依頼された変更のみを行う。「ついでに」のリネーム・リファクタは含めない
- 既存の機能・エンドポイント・イベントを、明示的な指示なく削除・変更しない
- 後方互換コードやレガシーサポートは、指示がない限り追加しない

## 配線忘れ（Forgotten Wiring）

- 新しいパラメータやフィールドを追加したら、呼び出し元から渡す経路があることを確認する
- `options.xxx ?? fallback` が常にフォールバックを使う状態になっていないか確認する
- テストでモック値を直接設定しても、実際の呼び出しチェーンを通らなければ配線されていない

## デッドコード

- リファクタ後に旧実装が残っていないか確認する
- 使われていない関数・型・エクスポート・インポートを削除する
- 「将来の拡張」のためのコードは書かない。必要になったときに書く

## 冗長な分岐

- if/else の両分岐が同じ関数を呼び、引数だけ異なる場合は統合する
- コールバック＋外部変数キャプチャで値を取得する代わりに、戻り値を使う

## レビュー指摘への対応

- 指摘されたコードを修正する。テストや文書の追加で「対応済み」としない
- 修正の diff に指摘対象のファイル・行が含まれていることを確認する

</instructions>
