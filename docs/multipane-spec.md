# マルチペイン分割 仕様（Issue #397）

Workspace とタスク詳細における UI レイヤーのペイン分割機能の仕様。tmux レイヤーのペイン分割
（`onSplitPane` / `WindowPaneTree`）とは独立した別機能である。

## 1. スコープとレイアウトモデル

- 分割エンジンは共有部品（`paneLayoutTree` / `usePaneLayout` / `usePaneRects` / `SplitLayout`）で、
  **2つのスコープ**にインスタンス化される。ネストはこの2階層まで。
  - **Workspace スコープ**: タブ = Workspace のタブ実体（terminal / task / unit / diff / browser / 各種リスト・フォーム）
  - **タスクスコープ**: タブ = タスク詳細のビュー（Description / Unit / Git / Summary / Commits / Diff）
    と、**アサイン済み tmux ウィンドウ（1 ウィンドウ = 1 タブ）**
- レイアウトは二分木。`split { dir: row|col, ratio 0.15–0.85, a, b }` / `pane { id, tabIds[], activeTabId }`。
  単一ペインの木は従来 UI と完全等価（見た目・挙動とも従来どおり）。
- タブは**常にいずれか1つのペインに所属**する。同一タブの複製表示はしない。
- ペインの最小サイズは 160px（サブツリーの必要最小を再帰計算してリサイズをクランプ）。

## 2. 分割・移動・マージ操作

分割の3経路:
1. **タブのドラッグ&ドロップ**: ペインの上下左右エッジへ → その方向に分割してタブが移動
2. **タブバー右端のボタン**: ◫（右に分割）/ ⬓（下に分割）→ 空ペインを作成
3. **タブのコンテキストメニュー**: 「右に分割して表示」「下に分割して表示」（モバイル/ドラッグ不能環境の代替）

ドロップゾーンは6種:
- **タブバー**: そのペインへマージ（x 座標から挿入位置を決定。同一ペイン内なら並べ替え）
- **中央**: そのペインへマージ（末尾追加）
- **上下左右エッジ**: その方向に分割
- ドラッグ中は結果をハイライトでプレビュー（タブバー=アクセント帯、中央/エッジ=破線オーバーレイ）

戻す / マージ:
- タブ右クリック「**次のペインへ移動**」(複数ペイン時のみ)
- タブバー右端 ⊟「**このペインを統合**」= 全タブを隣のペインへ一括移動してペインを畳む
- 単一タブの自己分割は許可（元側が空ペインとして残る）

ペインのライフサイクル:
- 最後のタブが閉じられた/移動したペインは自動で消え、隣が領域を引き継ぐ
- **意図的に作った空ペイン**は自動で畳まれない（reconcile は「無効タブの除去で空になったペイン」だけを畳む）。
  空ペインはプレースホルダー＋バー右端 ✕ で明示的に閉じる

## 3. 閉じる（非破壊）と削除（破壊）

- **× は常に非破壊**（表示から外すだけ）。Workspace タブは全て ×。タスク内は Description
  （固定アンカー・閉じられない）以外全て ×
- タスク内で閉じたビュー/ウィンドウタブの再表示: ＋ メニュー（閉じたビュー）／ウィンドウ一覧ドロップダウン
- **破壊操作はメニュー限定**: tmux ウィンドウの削除はウィンドウタブ右クリックメニューの
  Delete window（既存の Window Remove と同一処理・確認ダイアログ付き）のみ。× とは導線を完全分離。
  kill されたウィンドウのタブは全ペインから自動クローズ

## 4. フォーカスとオープン先のルール

- クリック（タブ/コンテンツいずれも）したペインが**フォーカスペイン**。分割時のみアクセント枠で明示
- サイドバー等から開く操作は**フォーカスペインに開く**。既に開いているタブは所属ペインでアクティブ化
  （重複オープンしない）
- **タスクのウィンドウ一覧からの選択は例外**: 選択したウィンドウタブが他ペインにあっても、
  **一覧を開いたペインへ移動して表示**する（「このペインでこれを見たい」という意図を優先）
- フォーカスペインのアクティブタブが、キー送信・オーバーレイ・グローバル focus の単一ターゲット。
  空ペインをフォーカスするとターゲットはクリアされる
- 別プロジェクトのタブを選択/フォーカスすると当該プロジェクトへナビゲートする（従来のタブ選択と同じ）

## 5. タスクスコープ固有

- ウィンドウタブ ID は pane サフィックスを正規化した `v-window:<server>/<window>`。接続時は
  `windows` から実ターゲット（pane 付き）を解決
- ウィンドウタブには稼働状態（working/blocked/finished）と respawn 中スピナーを表示
- ウィンドウ一覧ドロップダウン（ラベル＋件数＋▾）は従来 UI を維持: ウィンドウ/ペイン行・稼働表示・
  右クリックメニュー・+ Add Window。リストは縦スクロール可・右端揃えで画面内に収まる
- ターミナル（ウィンドウタブ）は「自ペインでアクティブ かつ タスクタブ可視」のときのみマウント
  （接続数はみえているペイン数で頭打ち）。テキスト系ビューも非アクティブ時はアンマウント（旧挙動と同等）
- ＋ メニューから「ブラウザ」タブ（`v-browser:<server>/<pageId>`、Workspace の browser タブと同じ
  CDP ブラウザ `BrowserView` を表示）を追加できる。クリックのたびに新しいインスタンスを作成（同一
  serverName でも共存可）。serverName はプライマリウィンドウ → `task.serverName` → 現在プロジェクトの
  先頭サーバーの順で解決し、解決できない場合は「ブラウザ」項目を disabled にする。マウント条件・タブ
  ID がレイアウト木に入るだけで復元される点はウィンドウタブと同様。ただしタブを閉じる（×）と
  `/browser/close-group` を呼びグループごと破棄する点、および keepalive をレイアウト在籍中（BrowserView
  のマウント状態とは無関係に）維持する点はウィンドウタブと異なる — 詳細は `useBrowserKeepalive` /
  `TaskPanel.tsx` の該当コメント参照

## 6. 永続化

- Workspace: `workspace-layout`（木 + focusedPaneId）。タブ実体は従来の `workspace-tabs` のまま
- タスク: `workspace-subtab-task` の per-task エントリを `{ layout, focusedPaneId }` に拡張。
  旧形式 `{ view, terminal }` は「全固定ビュー + 選択タブ」の単一ペインへ移行
- ロード時整合: ID 再シード・重複 ID/タブの拒否・消えたタブの間引き。タスクスコープは windows
  初回取得完了まで reconcile を保留（一時的な取得失敗で保存レイアウトを壊さない）
- Workspace スコープは「タブ実体 = 開いている集合」なので欠損タブを自動補完する。タスクスコープは
  「利用可能な集合」なので**除去のみ**（閉じたタブは復活しない）

## 7. モバイル（≤768px）

- 分割 UI は無効。従来の単一タブバー + 単一表示のまま。レイアウト木は保持され、デスクトップ復帰時に復元

## 8. 既知の制約・保留事項

- **クロスプロジェクト表示**: 別プロジェクトのタブをペインに可視のまま残した場合、`project` /
  `projectServers` 等は現在プロジェクトのものが供給される（フォーカスすれば当該プロジェクトへ遷移して
  解消）。恒久対応は「per-tab のプロジェクト文脈解決」か「他プロジェクトタブの同時表示制限」の二択で未決
- スコープ間（タスク内 ⇔ Workspace）のタブドラッグは不可。昇格はウィンドウタブ右クリック
  「ワークスペースのタブとして開く」のみ
- タブグループ（プロジェクト別グルーピング）はスコープ外
