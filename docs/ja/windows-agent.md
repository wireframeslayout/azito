# Windows のエージェントサーバー

Windows のマシンを、SSH 経由で AZITO のエージェントサーバーとして使うための文書です。準備、追加、使える機能、更新、削除、制約、困ったときの順に読めます。

- Windows の**ハブ**（AZITO 本体を Windows で動かす）の導入は [インストールとアップデート](./install-and-update.md) の「Windows 版の配布物」にあります。ハブとエージェントは別のものです。同じ Windows マシンに両方を置くこともできます。
- Windows のハブの**アプリ内更新**は、同じ文書の [Windows のハブのアプリ内更新](./install-and-update.md#windows-のハブのアプリ内更新)です。このページが扱うのは、ハブから見た Windows のエージェントの更新です（[更新](#更新)）。
- 機能ごとの詳細: [ファイル操作](./files.md#windows-のサーバーで使えるファイルの機能)、[タスクの実行](./tasks.md#windows-の-agent-でのタスクの実行371)、[ハーネス](./harness.md#windows)、[misao](./misao.md#windows-のエージェントへの導入)。

## 準備

Windows 側で用意するものです。管理者権限は要りませんし、求めません（ファイアウォールの規則の追加だけは、管理者の操作が要ることがあります。下の[管理者でないときの違い](#管理者でないときの違い)）。

| 前提 | 内容 |
|---|---|
| OpenSSH サーバー | Windows 側で有効化し、ハブから到達できること。既定シェルは **cmd.exe のままでよい**（PowerShell でも可）。ハブは先に OS を判定し、以後の確認は両方で同じに動く PowerShell スクリプトで行います。SSH で入るユーザーが、agent を動かすユーザーになります |
| Windows | x64 のみ。OS ネイティブのアーキテクチャで判定（ARM 版 Windows は x64 エミュレーション下でも理由付きで拒否）。Windows 10 1809（ビルド 17763）以降、Windows Server 2019 以降（`tar.exe` と `conhost.exe --headless` のため。preflight が確認します）。Windows の版（10 / 11 / Server）は表示だけで検査しない |
| Node.js v24+ | SSH セッションの PATH にあること |
| Git for Windows | `git.exe` が入っていること（`winget install --id Git.Git -e`。AZITO には同梱しません）。タスクの worktree と、ファイル画面の git の機能が使います。agent のホスト自身が、PATH（`PATHEXT` の拡張子付き）、次に標準の場所 `%ProgramFiles%\Git\cmd\git.exe`・`%ProgramFiles(x86)%\Git\cmd\git.exe`・`%LOCALAPPDATA%\Programs\Git\cmd\git.exe`（ユーザーごとの導入）の順に探します。タスクスケジューラの agent は最小の環境で起動して PATH が足りないことがあり、winget の直後は PATH がログオンし直すまで反映されないことがあるためです。使うのは `cmd\git.exe` だけで、`bin\git.exe`（ラッパー）や `mingw64\bin` は標準の場所として探しません。見つけた場所は覚え、見つからなかった結果は 30 秒だけ覚えるので、入れた直後も再起動なしで通ります。無いときは git の API が `git_not_found` で理由を返し、導入は止まりません。ハブが Windows のときの local サーバーも同じ規則で、ハブ自身が探します |
| Claude Code | ネイティブ版の `claude.exe` でも npm 版の `claude.cmd` でも動きます（PATHEXT で見つかること）。agent を動かすユーザーで、一度ログインしておいてください |
| Codex | 使うなら npm 版の `codex.cmd`（PATH にあること）。agent を動かすユーザーでログインしておいてください |
| Tailscale | 導入済みでサインイン済みであること。PATH に無くても `%ProgramFiles%\Tailscale\tailscale.exe` を探します |
| Windows ファイアウォール | `node.exe` への受信 TCP 3002 を許可し、Block 規則が無いこと（[追加](#追加)の手順 1） |

Claude Code と Codex は、タスクを実行するときに必要です。ファイル・git・ターミナルだけなら要りません。

### 管理者でないときの違い

導入、更新、削除は、SSH で入るユーザーが**管理者でなくても**できます（タスクスケジューラのタスクは、そのユーザーの権限で登録します）。違いは次の 3 点です。

- **ファイアウォールの規則を、AZITO は自分では追加できません。** 昇格した（管理者の）SSH セッションなら導入が規則を追加します。昇格していなくても、**すでに条件を満たす有効な許可の規則があれば**、規則を作らずにそのまま続行します（その場合、削除の firewall の手順は `ありませんでした` になります）。許可が無く、規則を追加もできないときだけ、**何も転送する前に止まり**、管理者の PowerShell で 1 回だけ実行するコマンドを表示します。実行してから、もう一度導入します。
- **見えないプロセスがあります。** 削除や片付けでは、フォルダーから動いているプロセスを調べますが、システムや他のユーザーのプロセスは、普通のユーザーの SSH セッションからは読めません。AZITO は読めない自分のプロセスの扱いを決めていますが（[削除](#削除)）、他のユーザーのプロセスは範囲外です。
- **Defender などの保護されたプロセス**は、管理者でも読めないことがあります（[制約](#制約)）。

## 追加

Servers → Add → Agent で、種類に Windows のホストの SSH 先（`user@host:port`、Tailscale SSH の `none` 認証も可）を指定します。ハブはまず OS を判定します。Windows と分かれば、preflight（OS・アーキテクチャ・版・Node・`tar.exe`・`conhost.exe`）を確認し、問題があれば理由付きで止まります。

OS の判定は、sh・cmd.exe・PowerShell で出力が変わる 1 本の `echo AZITO_OS:%OS%:$?`（変数を読まないので `set -u` でも動く）で行い、どれにも当てはまらない応答は推測せずエラーにします。

導入で行うこと:

1. **Windows ファイアウォールの確認。** Windows は、規則が許可するまでプログラムへの受信を遮ります。初回の許可ダイアログはデスクトップに出るだけで、SSH のセッションには出ません。導入は、有効な受信の規則をすべて（ポート・プログラム・アドレスのフィルターごと）読み、TCP 3002・`node.exe`・agent が bind する Tailscale の IP について次のように判定します:
   - **許可（Allow）** 規則は、次のすべてを満たすときだけ数えます: プロトコルが TCP か Any、ローカルポートが 3002 か Any（`3000-3010` のような**範囲指定は読まない**ので数えません）、プログラムが `node.exe` か Any、リモートアドレスが Any かタンネル範囲 `100.64.0.0/10`（LocalSubnet など**他のリモートアドレスに絞った規則**はハブに届かないので数えません）、ローカルアドレスが Any か agent の IP、プロファイルが Tailscale アダプターのもの（`Get-NetConnectionProfile`。取れないときは Any か Public）を含むこと。Tailscale アダプターが Public のとき、Private だけを許可する規則は数えません。
   - ハブを止めうる、有効な受信の **Block** 規則があれば、その DisplayName を示して止まります。対象は、`node.exe` か全プログラムに対するポート 3002（それを含む範囲指定も）で、agent のローカルアドレスに適用され、リモートアドレスがタンネルを含み（Any・重なる範囲・`Internet`）、Tailscale アダプターのプロファイルに適用されるものです。別のポート・別のリモートネットワーク・別のプロファイルの Block は数えません（初回のダイアログをキャンセルすると Windows が作ります）。Block は Allow より優先されるので、その横に追加はしません。
   - 条件を満たす Allow も Block も無く、SSH のセッションが管理者（昇格したトークン）なら、このプログラム・このローカルアドレス・`100.64.0.0/10` からだけ、の `AZITO Agent (TCP 3002)` を追加します。昇格していなければ、**何も転送する前に止まり**、管理者の PowerShell で 1 回だけ実行するコマンドを表示します:
   `New-NetFirewallRule -DisplayName "AZITO Agent (TCP 3002)" -Direction Inbound -Action Allow -Protocol TCP -LocalPort 3002 -Program "C:\Program Files\nodejs\node.exe" -LocalAddress <Tailscale の IP> -RemoteAddress 100.64.0.0/10 -Profile Any`（実際のパスと IP が入って表示されます）。
   - 規則は、読めれば現に有効なもの（`ActiveStore`。グループポリシーを含む）、読めなければローカルのもの（`PersistentStore`）を読みます。そのため、このセッションに読ませないホストでは、グループポリシーが配る Block は見えません。規則のインターフェースの種類による制限も見ません。ホストが答えられない場合（NetSecurity モジュールが無いなど）は止めません。ヘルスチェックが失敗したとき、ファイアウォールを名指しします。
2. **転送。** バンドルを SFTP で `%USERPROFILE%\.azito\agent\` へ送り、ホスト上で SHA256 を照合します。
3. **展開。** 標準の `tar.exe` で `%USERPROFILE%\.azito\agent\<version>\` に展開します（先に、フォルダーの外へ出るパスが無いか検査します）。フォルダーは本人だけが読めます。symlink は使いません。下のタスクが版のフォルダーを直接指すので、再導入のたびにタスクを登録し直します。
4. **設定。** トークン、bind するアドレス（Tailscale の IP）、ポートは `%USERPROFILE%\.azito\agent\agent.env` に書きます。本人だけが読める ACL にし、そうなっていなければハブが検査して先へ進みません。agent は `conhost.exe --headless node.exe --env-file=<そのファイル> <版のフォルダー>\azito-agent.cjs` で起動するので、起動用のスクリプトは挟まず、デスクトップにコンソールウィンドウも出ません。設定ファイルは、トークンを書く前に本人専用で作成してから置き換えます。既存の `agent.env` には書き込みません。agent 自身のログは `%USERPROFILE%\.azito\agent\agent.log` に書かれます。
5. **常駐。** タスクスケジューラのタスク `AzitoAgent` を登録します。**SSH で入ったユーザーのログオン時に起動**し（ユーザー権限、失敗時は再起動）、続けて `/Run` します。
6. **ヘルスチェック。** Linux と同じです。再導入は、新しい agent が応答するまでをひとつの操作として扱います。それまでの旧タスク定義・設定・同じ版のフォルダー・稼働状態は退避しておき、新しい agent が起動しない・応答しないときは**元に戻し**（旧 agent を再起動し）ます。ハブが持つトークンとホストの `agent.env` が食い違ったまま残ることはありません。退避したものは、新しい agent の健全を確認してから削除します。
7. **misao。** agent が健全になったあと、同梱の **misao**（ペインサーバー）を入れます。タスクスケジューラのタスク `AzitoMisao`（ログオン時に起動）とフォルダー `%USERPROFILE%\.azito\misao` で、詳しくは [misao](./misao.md#windows-のエージェントへの導入) を参照してください。Windows には tmux が無いので、ペインサーバーは misao だけで、新しいサーバーの既定の mux は misao になります。misao だけが失敗しても agent は導入済みのままで、理由が `misaoError` として導入成功と並べて出ます。
8. **ハーネス。** タスクを実行するには、AZITO ハーネス（`/azt-*` スキルとフック）が要ります。サーバー詳細 → Setup → Install Harness から入れます。Windows では bash の代わりに Node（`setup.mjs`）で入れます。詳しくは [ハーネス](./harness.md#windows) を参照してください。

ハブが追加時に決めるもの（Tailscale の IP など）は、他の agent サーバーと同じです。ハブへの届き方の設定は [セキュリティ設定](./security-setup.md) にあります。

## 使える機能

ハブはエージェントから OS（`hostProfile`）を受け取り、サーバー一覧とサーバーの概要に表示します。操作ごとに、いまのコードの経路で閉じるかどうかを決めます（判定は `@azito/shared` の `hostFeatureSupport` の 1 つの表で、各行を閉じる経路はコメントに書いてあります）。閉じた入口はフォーカスできる（`aria-disabled`）まま何もせず、理由を文字かツールチップで出し、`aria-describedby` で結び付けます。それでもハブに届いた操作は、理由付きの `unsupported_os`（501）で断られ、UI はその理由をそのまま出します。タスクは、実行先のサーバー（タスク自身のサーバー、無ければプロジェクトの唯一のサーバー。ハブと同じ規則）で判定します。

| 機能 | Windows のエージェント | 理由・issue |
|---|---|---|
| サーバーの追加（preflight・agent の導入・OS の自動判定）、Setup からの再導入 | 使える | — |
| ホスト上の agent の更新 | 使える（[更新](#更新)） | — |
| ホスト上の agent の削除 | 使える（[削除](#削除)） | Linux / macOS のホストからの削除は #499 |
| misao（ペインサーバー）と、Setup からの導入・更新 | 使える。misao の更新は agent の更新とは別 | — |
| シェルだけの新しいウィンドウ | 使える（cmd.exe） | — |
| ファイル（一覧・読み・書き・作成・削除・名前の変更。`IFileOps`）、ファイル名の検索、ファイルの中身の検索（`rg` があれば `rg`、無ければ内蔵の検索。結果のパスは相対の `/` 区切り）、ディレクトリの補完。詳しくは [ファイル操作](./files.md#windows-のサーバーで使えるファイルの機能) | 使える | — |
| git の diff・履歴・ワークツリーの切り替え・ブランチの検索・リポジトリの検出 | 使える（Git for Windows が必要。無ければ API は `git_not_found`（501）で、理由を各画面のエラーに出す） | — |

## 動き方と運用

**agent は、そのユーザーが Windows にログオンしている間だけ動きます**（コンソールでも、リモートデスクトップでも）。再起動後はログオンするまで何も起動せず、ログオフすると agent は止まります。ログオフしても動き続けるサーバーには、自動ログオンなど別の方式が要りますが、まだ用意していません。misao のタスク `AzitoMisao` も同じで、ログオフ中はデーモンも動きません。

**落ちたとき。** agent のタスクの RestartOnFailure は発火しません。`conhost.exe --headless` は子の終了コードを常に 0 で返し、タスクスケジューラは非 0 の終了コードでもタスクを再起動しないためです（Windows CI での実測）。そのため**ハブが動いている間は、ハブが戻します**。ハブは Windows の agent を 15 秒ごとに確認し、応答しない agent があれば、約 1 分後に再起動（ハブの起動時と同じ、タスクの `/Query`・`/End`・`/Run`）を試み、以降は 15 分を上限に間隔を倍々に延ばします。agent が応答すれば最初からやり直します。試すのはサーバーごとに 1 本で、そのサーバーの導入・更新の最中には行わず、編集で外れたサーバーも対象外です。**ハブが止まっている間は戻りません。** 手で止めた（`schtasks /End /TN AzitoAgent`）ものは落ちたものと区別できないので、ハブが起動し直します。止めたままにするには、サーバーをハブから外すか、タスクを無効にしてください（`schtasks /Change /TN AzitoAgent /DISABLE`。無効のタスクはハブが黙って飛ばします）。Unix の agent は対象外です（systemd の `Restart=` があります。nohup で起動したものはハブの起動時の版確認でだけ戻ります）。

| 操作 | 方法 |
|---|---|
| 再起動 | ハブが agent に届かないとき、タスクを再起動します（`schtasks /End` のあと `/Run`）。または Setup の行の「Reinstall」 |
| 停止 | ホスト上か SSH で `schtasks /End /TN AzitoAgent`、またはタスクスケジューラの「終了」。agent はタスクが動かす `conhost.exe` に付き従い、それがいなくなって数秒で終わります（手で `node azito-agent.cjs` を起動したものは別です）。そのとき Windows が親のプロセス ID を別のプロセスに再利用していても、親の作成時刻を比べて約 30 秒以内に気づきます。それでも残る場合は、Setup の行から停止してください（ハブは `--env-file` の引数で agent を終わらせます）。次のログオンでまた起動します。起動させたくなければ `schtasks /Change /TN AzitoAgent /DISABLE` も（ただし、ハブが動いている間は[上のとおり](#動き方と運用)起動し直すので、サーバーをハブから外すか、タスクを無効にします） |
| ログ | agent: `%USERPROFILE%\.azito\agent\agent.log`、misao: `%USERPROFILE%\.azito\misao\misao.log` |
| 削除 | [削除](#削除) |

本物の agent の隣で 2 つ目を試すときは、ハブの環境変数 `AZITO_WIN_AGENT_TASK_NAME`、`AZITO_WIN_AGENT_DIR`（ユーザーのホーム直下のフォルダー）、`AZITO_WIN_AGENT_PORT` を設定します。既定は `AzitoAgent`、`.azito\agent`、`3002` です。これは試験用です。サーバーごとには保存されないので、これらを付けずに起動したハブは既定のタスクを探します（使われているときはハブのログに 1 行出ます）。その一時ハブだけで使ってください。

## 更新

ハブの起動時に、登録済みの agent サーバーの版を確認します（判定は他の agent と同じ、バンドルの SHA256）。Windows の agent で版が違えば、導入と同じ手順で更新します。実行中のタスクがあれば延期し、次のハブの起動時に確認し直します。手動では、サーバー詳細 → Setup → Agent Server の「Reinstall」で同じ手順が動きます。

更新の流れ:

1. 何も止める前に、ファイアウォールの規則を導入と同じ方法で確かめます（許可が足りなければ、昇格していれば規則を足して続行し、昇格していなければここで止まります。止まったときは元の agent は動いたままです）。
2. 新しい版を配置し、起動して、ヘルスチェックを待ちます。**トークンは今の agent のものを使い回す**ので、ハブの設定を変える必要はありません。
3. 新しい agent が応答すれば確定し、退避しておいた前の版・設定・タスクを消します。応答しなければ、前の版・設定・タスクに**戻して**前の agent を起動し直します。配置の途中で失敗したときも、元が動いていたなら前の agent の応答を確かめ、結果をエラーの文に入れます。
4. ロックの中でサーバーの宛先・トークン・種類・OS・実行中の状態を読み直し、変わっていたらその更新は行いません（`skipped`）。更新と手動の再導入が重なっても、古いトークンを書き戻すことはありません。

古い版の片付け: 更新が成功したあと、`%USERPROFILE%\.azito\agent\` には**今の版と直前の版だけ**を残し、それより古い版のフォルダーを消します。フォルダーは、12 桁の 16 進の名前（大文字小文字を区別）のものだけが対象です。`*.prev` や一時フォルダー、自分で作ったフォルダーには触れません。リンク（ジャンクション・シンボリックリンク）は辿らず消しません。使用中で消せないフォルダーは、警告を出して残し、次の更新でもう一度消そうとします。

misao の更新は別です。agent の更新は misao に触れません（動いているデーモンを止めないため）。misao は Setup の行の「Update misao」（確認のあと、前の版を止めて切り替えて起動し、失敗すれば戻す）で、自分の判断で更新します。[misao](./misao.md#windows-のエージェントへの導入) の `update()` を参照してください。

更新が失敗したときは、画面のエラーに理由と、前の agent が動いているかが出ます。続けて失敗する場合は[トラブルシューティング](#トラブルシューティング)を見てください。

## 削除

サーバーの削除の確認に、2 つの選択があります（対象は Windows のエージェントだけです。Linux / macOS のホストからの削除は #499 で、今は手作業です）。

- **ホストからもエージェントを消す**（既定はオン）。サーバーを削除する前に、ホストから agent を消します。
- **misao も消す（窓はすべて閉じます）**（既定はオフ。上の選択をオンにしたときだけ選べます）。

ホストで行うこと（結果は手順ごとに `消しました` / `ありませんでした` / `失敗` / `行いませんでした` で返ります）:

- **タスク `AzitoAgent`** の終了と登録解除。導入が書いたとおりのタスク（唯一の Exec が導入の形と文字どおり一致し、このホストの node.exe を使うもの）だけを対象にします。そうでなければ触れず、理由を返します。
- **エージェントのフォルダー** `%USERPROFILE%\.azito\agent` の削除。ドライブの直下まで経路にリンクが無いときだけ消します。
- **プロセスは AZITO が止めません。** タスクを終了したあともフォルダーから動いているプロセスが残っていれば、フォルダーは消さず、その pid とパスを返すので、手で止めてください。「フォルダーから動いている」は意図して広く読みます: プログラムまたはコマンドラインが、フォルダーを（`/` と `\`、大文字小文字、長い名前と 8.3 名、ホームより下の部分のどれの綴りでも）含むプロセスです。プログラムかコマンドラインをホストが返さない自分のプロセスがあれば、それも知らせます。ほかのユーザーのプロセスは SSH のセッションからは見えません。
- **misao も消す**を選んだとき: misao のタスク `AzitoMisao` とフォルダー `%USERPROFILE%\.azito\misao` も消します（窓はすべて閉じます）。タスクを終了しても misao のデーモンは終わらないので、そのタスクのパイプを提供しているプロセスを Windows に尋ね、それが自分のユーザーの `misao.exe` で、misao のフォルダーの下にあるときだけ、そのデーモン自身の停止（タスクが走らせる release の `misao.exe stop`）を 1 回頼みます。パイプを持つのがそれ以外のものなら触れず、理由を返します。同じホストの Windows のハブの misao（タスク `AzitoHub` が持つフォルダー、またはタスク無しで動いているハブのプロセスがあるとき）や、タスクが起動したと確かめられない misao は消さず、理由を返します。
- **ファイアウォールの規則は消しません。** Name と、確かめたうえで消すコマンドを一覧にして返します。サーバーを削除したあとも、同じ一覧をコピーできるコマンド付きのダイアログで見せます。

**残るもの。**

- ファイアウォールの規則 `AZITO Agent (TCP 3002)`（導入が追加していた場合）: 管理者の PowerShell で `Get-NetFirewallRule -DisplayName "AZITO Agent (TCP 3002)"` を実行して一覧にし、導入が追加した規則（TCP 3002 の Allow、この agent の node.exe、100.64.0.0/10 から）であることを確かめて、Name で消します: `Remove-NetFirewallRule -Name '<Name>'`。
- AZITO ハーネス（`%USERPROFILE%\.azito\harness*`、`~\.claude\settings.json` のフック）: 自動では消しません。手作業で消してください。
- 「misao も消す」を選ばなかったときの misao（タスクとフォルダー）。

**失敗したとき。** ホストの削除が一部でも失敗したら、サーバーの行は消えません。手順ごとの結果が画面に残り、次から選べます。

- **もう一度試す**: 理由（プロセスが残っている、など）を直してから再実行します。
- **サーバーの登録だけを削除**: ホストに残ったものは手作業で消します。
- **やめる**: サーバーの登録を残して画面を閉じます。済んだホスト側の削除（終了したタスクなど）は元に戻りません。

**ホストがオフラインのとき。** ホストに届かないと、削除はホストの状態を何も変えません。「ホストからもエージェントを消す」をオフにして、サーバーの登録だけを消してください。ホストに残ったものは、次の手作業で消します。

手作業で消す手順（UI を使わなかったとき、オフラインだったとき）:

1. `schtasks /End /TN AzitoAgent`
2. `schtasks /Delete /TN AzitoAgent /F`
3. `%USERPROFILE%\.azito\agent` を削除
4. ファイアウォールの規則は上のとおり（確かめてから消す）
5. misao も消すなら `schtasks /Delete /TN AzitoMisao /F` と `%USERPROFILE%\.azito\misao` の削除（窓はすべて閉じます。デーモンが動いていれば、**タスクの登録を解除する前に**、タスクの定義（`schtasks /Query /TN AzitoMisao /XML`）で対象の `misao.exe` と `--socket` のパイプを確かめ、`$env:MISAO_SOCKET = '<対象のパイプ>'; & '<対象の misao.exe>' stop` を PowerShell で実行してください。パイプの指定が無いと、止まらないか別のデーモンを止めることがあります）

## 制約

- **ログオフで止まります。** agent も misao も、ユーザーのログオンに付いたタスクです（[動き方と運用](#動き方と運用)）。
- **Defender などの保護されたプロセスは読めません。** 削除や片付けでフォルダーを使っているプロセスを調べるとき、読めないプロセスはあります。AZITO はフォルダーを持ちうる種類のものだけを数えますが、判断できないプロセスが残るときは、フォルダーを消さずに知らせます。
- **同じユーザーの悪意のあるプロセスからは守りません。** 削除や片付けの安全の確認（タスクが導入のものか、パイプの持ち主が自分の misao か、リンクを辿らないか）は、事故と取り違えを防ぐためのものです。確認から実行までの間に、同じユーザーのプロセスがデーモンやフォルダーを差し替えるような競合は、受け入れた限界です（そのユーザーは外のファイルを自分で消せるので、境界を越えません）。長い名前と 8.3 名が混ざったパスの見逃しも同じ扱いです。
- **TUI のサイズ変更。** Windows のペインで動く Node の TUI（Claude Code など）は、端末の大きさの変更（ConPTY の resize）に追従しません。ペインは 120x40 で始まるので、ブラウザーの窓の大きさを変えても、TUI の描画は変わらないことがあります。misao 側の既知の制約です。
- **コード配信・隔離・ブラウザー実行環境は使えません**（[使える機能](#使える機能)の表）。
- **Windows のペインは cmd.exe で、シェルの構文を含むコマンドは起動できません**（[使える機能](#使える機能)の表）。

## トラブルシューティング

| 症状 | 原因と手順 |
|---|---|
| 操作が `unsupported_os`（501）で断られる、または入口が灰色で理由が出る | その機能が Windows のホストで閉じています。理由はそのまま画面に出ます。閉じているのは、tmux、コード配信（#464）、隔離（#464）、ブラウザー実行環境（#500）、Linux / macOS のホストからの削除（#499）、シェルの構文を含むコマンドの起動、いくつかの respawn（[使える機能](#使える機能)）です |
| git の画面やタスクが `git_not_found`（501）になる | ホストに Git for Windows がありません。`winget install --id Git.Git -e` で入れてください（再起動は要りません。見つけた結果は 30 秒で捨てます）。標準の場所は[準備](#準備)の表にあります。探した場所はエラーにも出ます |
| 導入が、ファイアウォールのコマンドを表示して止まる | SSH のセッションが管理者ではなく、許可の規則がありません。管理者の PowerShell で表示されたコマンドを 1 回実行して、もう一度導入します（[追加](#追加)の手順 1） |
| 導入が、Block 規則の DisplayName を示して止まる | 受信の Block 規則がハブを止めます。その規則を確かめて無効にするか消してください。Block は Allow より優先されるので、AZITO は横に Allow を足しません |
| agent に届かない（オフライン、`401`） | 次を順に見てください。(1) ユーザーがログオンしているか（ログオフすると止まります）。(2) タスク `AzitoAgent` が動いているか（`schtasks /Query /TN AzitoAgent`）。無効になっていないか。(3) ファイアウォールが TCP 3002 を許可しているか、Block が無いか。(4) Tailscale が両端でつながっているか。(5) トークン: 401 はハブの持つトークンとホストの `agent.env` の食い違いです。Setup の行の「Reinstall」で揃います（再導入は、新しい agent が応答するまで元に戻せる形で行います） |
| 更新が失敗する | 画面のエラーに理由があり、前の agent は動いているか、元に戻されます。配置の途中で止まったときは、`%USERPROFILE%\.azito\agent\` に `*.prev`（退避した前の版・設定）が残ることがあります。**次の導入・更新は、`*.prev` が残っていると進みません。** エラーに残っている名前が出ます。いま入っている agent が動いていればそれらを消し、動いていなければ `.prev` を外した元の名前に戻してから、もう一度行います（トークンを持つ唯一の写しかもしれないので、AZITO は自分では消しません）。使用中の古い版のフォルダーは、警告のあと次の更新で消えます |
| 削除が `失敗` で止まる | 手順ごとの結果を読んでください。(1) タスクが導入のものと違う: 触らずに残します。不要なら `schtasks /Delete /TN AzitoAgent /F` で消します。(2) フォルダーから動いているプロセスがある: 表示された pid とパスのプロセスを止めてから「もう一度試す」。(3) 読めない自分のプロセスがある: タスクマネージャーなどで確かめて、不要なものを止めます。(4) misao が行われなかった: 理由を読みます（Windows のハブのもの、タスクが起動したと確かめられないもの、など）。ハブのものなら消してはいけません。(5) 解決しなければ「サーバーの登録だけを削除」にして、残ったものを手作業で消します |
| タスクが `bypass_permissions_dialog` で失敗する | Claude Code の「Bypass Permissions mode」の確認ダイアログが出ています。AZITO は、Claude のワーカーを起動する前にホストの `~\.claude\settings.json` へ受け入れを書き込みます（[タスク管理](./tasks.md#claude-code-の確認ダイアログbypass-permissions-mode)）。それでも出るときは、ホストで一度 `claude --dangerously-skip-permissions` を手で起動して受け入れてください。ファイルが壊れた JSON だと書き換えないので、実行ログの理由を見ます |
| Codex のタスクがフォルダーの信頼の確認で止まる | Codex は初回にフォルダーの信頼を尋ねることがあります。Claude Code と違って、AZITO は Codex の信頼を先には書きません。ホストで一度、そのフォルダーで `codex` を手で起動して信頼してください（Add Window で窓を作って受け入れてもかまいません）。実機での確認は進行中です |
| タスクの窓が開かない、`claude` / `codex` が見つからない | プログラムが PATH / PATHEXT で見つかりません。agent を動かすユーザーの PATH を確認してください（タスクスケジューラの agent は最小の環境で始まることがあります。変更したら、ログオンし直すか、Setup の行から Reinstall します） |
| 日本語の名前や空白を含むフォルダーで misao のタスクが動かない | [misao](./misao.md#windows-のエージェントへの導入) のとおり、そのようなパスは PowerShell の起動スクリプト経由になります。それでも起動しないときは、ログのファイル（`misao.log`）を見ます |

## Windows のハブとの関係

- ハブ自身を Windows で動かすとき（導入、タスクスケジューラのタスクとしての常駐、制約）は [インストールとアップデート](./install-and-update.md#windows-版の配布物) を参照してください。ハブのアプリ内更新は、同じ文書の [Windows のハブのアプリ内更新](./install-and-update.md#windows-のハブのアプリ内更新) です。
- Windows のハブから、Windows の agent を含む SSH / agent のサーバーを使う準備（ssh-agent、鍵、ホストキー）は [Windows のハブから SSH / エージェントのサーバーを使う準備](./install-and-update.md#windows-のハブから-ssh--エージェントのサーバーを使う準備) にあります。
- Windows のハブの local サーバーは misao だけ（tmux は無い）です。ファイルとタスクの扱いは Windows の agent と同じです（[misao](./misao.md#windows-のハブ自身の-misao)）。
