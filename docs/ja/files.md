# ファイル操作ガイド

## ファイルエクスプローラー

ワークスペースのアクティビティバーで **Files** モードを選択すると、プロジェクトのサーバー上のファイルツリーが表示されます。

### 基本操作

- ディレクトリをクリックして展開・折りたたみ
- ファイルをクリックするとメインエリアにプレビュータブが開く
- パンくずリスト（ブレッドクラム）で現在のパスを確認可能

### ファイルツリーの構成

ファイルツリーはプロジェクトの `workingDirectory` を起点として表示されます。ディレクトリの展開はサーバーに対してリアルタイムにリクエストされるため、最新のファイル状態が反映されます。

### ファイル・フォルダの作成／削除／名前変更

ファイルツリーのノードを右クリック（モバイルでは長押し）すると、コンテキストメニューから以下の操作ができます。

| 操作 | 内容 |
|---|---|
| 新規ファイル | 選択したディレクトリ配下にファイルを作成 |
| 新規フォルダ | 選択したディレクトリ配下にフォルダを作成 |
| 名前の変更 | ファイル・フォルダ名を変更 |
| パスをコピー | フルパスをクリップボードにコピー |
| ダウンロード | ファイルをダウンロード（フォルダは非対応） |
| 削除 | 確認モーダルを表示したうえで削除 |

作成・名前変更はツリー上のインライン入力欄で行い、削除のみ確認モーダルを挟みます。サーバー側では作成・保存・名前変更・削除のすべての書き込み操作について、対象がプロジェクトの `workingDirectory` 配下に収まっているかを常に検証しており、範囲外のパスは拒否されます。削除操作ではこれに加えて、`.git` ディレクトリおよびルートディレクトリ自体の削除も拒否されます。

### worktree ルートの切り替え

サイドバー上部のルートスイッチャー行から、現在表示している worktree（ブランチ）を切り替えられます。このルートスイッチャー行には、選択中の worktree の変更ファイル数がバッジで表示されます。クリックするとピッカーが開き、プロジェクトサーバー上の worktree 一覧（ブランチ名・紐づくタスクの状態）が絞り込み検索付きで表示されます。タスク実行中に作成された worktree にはタスクの状態が併記され、`.worktrees/task-<タスクID>` 形式のパスを持つ worktree のうち対応するタスクが見つからないものは「孤立」として区別されます。

## ファイル検索

サイドバーの検索モードでは、ファイル名・ファイル内容を横断的に検索できます。

- 検索欄の右側に `Aa`（大文字小文字を区別）・`ab`（単語単位）・`.*`（正規表現）の3つのインライントグルがあり、有効にした条件で絞り込めます
- 詳細を開くと「含めるファイル」「除外するファイル」に glob パターンを指定可能です（既定の除外例: `node_modules`, `.git`, `dist`, `.worktrees`）
- ファイル内容の検索は、サーバー上に `rg`（ripgrep）があれば `rg` を使います（速いので、入れておくのがおすすめです）。`rg` が無い Unix のサーバーでは `grep` を、`rg` が無い Windows のサーバー（Windows には `grep` もありません）では AZITO 自身が Node で書いた検索を使います。どれで検索したかは、検索結果の上の小さなラベル（ripgrep / grep / 内蔵）に出ます
- Node で書いた検索は `rg` と完全には同じではありません。同じなのは、既定の除外ディレクトリ（`node_modules`・`.git`・`dist`・`.worktrees`）、含める / 除外するファイルの glob の読み方（`rg -g` と同じ。`src/*.ts` はルート直下の `src` 内だけ、`src/private/**` はその下すべての除外）、1 ファイル 5 行までの上限、結果全体 1 MB までの上限、バイナリ（NUL バイトを含むファイル。BOM 付きの UTF-8 / UTF-16 は文字として検索）の読み飛ばしです。違うのは次の点です。10 MB を超えるファイルは内蔵の検索だけが読み飛ばします（`rg` には上限がありません）。`.gitignore` を見ないので、`rg` なら飛ばすファイルも検索します。隠しファイル（`.env`、`.github/` など）も検索します（`grep` と同じです）。正規表現は JavaScript の文法で、「単語単位」は ASCII の英数字と `_` だけを単語の文字とみなします。`rg` も `grep` も見つからない Unix のサーバーでも、同じ検索に切り替わります。新しい検索の操作を持たない古い agent では `agent_outdated` として断ります（agent を更新してください）
- 結果のパスは、どの経路でも検索ルートからの相対パス（区切りは `/`）です
- 検索範囲もプロジェクトの `workingDirectory` 配下に限定されます

## Windows のサーバーで使えるファイルの機能

Windows のエージェントサーバー、および Windows のハブ自身（local サーバー）では、ファイルの機能のうち次のものが使えます。いずれも Linux / macOS と同じ画面・同じ API で、ファイルの操作はホスト自身の Node が行います（シェルのコマンドには頼りません）。

| 機能 | Windows での扱い |
|---|---|
| 一覧・読み取り・書き込み・作成・削除・名前の変更 | 使えます。削除は作業ディレクトリ自身と `.git`（大文字小文字・末尾のドットや空白の違いも同じ扱い）を拒否します |
| ファイル名の検索 | 使えます（ホスト上で 1 回ツリーを歩いて照合します） |
| ファイルの中身の検索 | 使えます。`rg` が入っていれば `rg`（速いので、入れておくのがおすすめです）、無ければ内蔵の検索です。内蔵の検索と `rg` の違いは上の「ファイル検索」を参照してください。結果のパスは、どちらでも検索ルートからの相対パス（`/` 区切り）で、画面がそれを Windows のパスに戻してファイルを開きます |
| ディレクトリの補完 | 使えます（プロジェクト設定の作業ディレクトリの入力欄） |
| 作業ディレクトリのパス | Windows のパスを設定できます。ドライブのパス（`C:\work\app`）、UNC（`\\server\share\app`）、ホームからの `~\work` です |
| git（差分・履歴・ワークツリー・ブランチの検索・リポジトリの検出） | 使えます。ホストに **Git for Windows**（`git.exe`）が必要です（`winget install --id Git.Git -e`。エージェントのサーバーも、ハブの local も、そのホスト自身が探します）。`git.exe` が見つからないときは、API が理由付きの `git_not_found`（501）を返し、UI は各画面のエラー表示にその理由（入れ方と探した場所）をそのまま出します。見つけ方は [Windows のエージェントサーバー](./windows-agent.md#準備)を参照してください |

作業ディレクトリへの閉じ込め（作業ディレクトリの外へ出る操作の拒否）は、Windows のパスの規則で判定します。比べる前に両側を実在のパス（ディスク上の綴り）に解決するので、入力の大文字小文字の違いは問われません。`\` と `/` はどちらも区切りです。

## ファイルプレビュー

ファイルをクリックすると、メインエリアにプレビューが表示されます。

### シンタックスハイライト

highlight.js による多言語対応のコードハイライトに対応しています。

| 言語 | 拡張子 |
|---|---|
| TypeScript | `.ts`, `.tsx` |
| JavaScript | `.js`, `.jsx` |
| JSON | `.json` |
| CSS | `.css` |
| XML / HTML | `.xml`, `.html`, `.svg` |
| Markdown | `.md` |
| Python | `.py` |
| Bash / Shell | `.sh`, `.bash` |
| YAML | `.yml`, `.yaml` |
| SQL | `.sql` |

上記は明示的に登録されている言語です。それ以外も highlight.js の自動検出が試みられます。

#### Markdown の表示モード

Markdown ファイルは3つの表示モードを切り替えられます。

| モード | 説明 |
|---|---|
| Source | ソースコードとして表示（シンタックスハイライト付き） |
| Preview | レンダリングされた Markdown として表示 |
| Split | 左右に Source と Preview を並べて表示 |

### 画像プレビュー

以下の形式の画像ファイルはインラインでプレビュー表示されます。

| 形式 | 拡張子 |
|---|---|
| PNG | `.png` |
| JPEG | `.jpg`, `.jpeg` |
| GIF | `.gif` |
| WebP | `.webp` |
| SVG | `.svg` |
| BMP | `.bmp` |
| ICO | `.ico` |
| TIFF | `.tiff`, `.tif` |

画像はサーバー経由のプロキシエンドポイントから取得され、Base64 エンコードで表示されます。

### PDF プレビュー

PDF ファイル（`.pdf`）は埋め込みビューアーでプレビュー表示されます。

### ストレージ画像プレビュー

ファイルストレージ（MinIO）のファイル一覧で画像ファイルを選択すると、サイドバー内にプレビューが表示されます。モバイルでは画像プレビューをクリックするとサイドバーが自動的に閉じます。

## ブラウザ内エディター

Markdown 以外のテキストファイルはプレビューエリアがそのまま CodeMirror 6 ベースのエディターになっており、追加の「編集モード」への切り替えなしで直接編集できます。Markdown ファイルは Source（ソース）/ Preview（プレビュー）/ Split（分割）の3表示モードを切り替えられ、既定は Preview です。既定の Preview は閲覧専用で、編集するには Source または Split に切り替える必要があります。

- **vim モード**: エディター右上のトグルで vim キーバインドを有効化できます（設定は端末に保存され、次回以降も維持されます。モバイル幅では既定でオフ）。vim モードでは `:w` での保存にも対応します
- **保存**: 編集後は保存操作で `PUT /api/servers/:name/files/content` に送信されます
- **競合検出**: 保存前に取得したファイルの mtime と sha256 ハッシュ（`baseMtime`/`baseHash`）をリクエストに含め、サーバー側の現在値と一致しない場合は保存が拒否されます（競合状態）。競合時はバナーが表示され、サーバー側の最新内容を再読み込みするか、自分の編集内容で強制上書き（`force`）するかを選べます

## Git 差分表示

ワークスペースの Diff タブでは、worktree の変更内容を3つのスコープで切り替えて表示できます。

| スコープ | 内容 |
|---|---|
| 未コミット | 作業ツリーの未コミット変更（未追跡ファイルを含む） |
| base と比較 | base ブランチとの merge-base を基準にした差分。「未コミットを含める」トグルで作業ツリーの変更を含めるかどうかを切り替え可能 |
| コミット | 選択したコミット単体の diff |

## ダウンロード

ファイルプレビュー画面の上部にあるダウンロードボタンをクリックすると、ファイルをブラウザにダウンロードできます。

### 制限事項

- 最大ファイルサイズ: **50MB**
- バイナリファイルにも対応（テキスト以外のファイルもダウンロード可能）
- ダウンロードは AZITO サーバー経由のプロキシエンドポイントを通じて行われます

### エンドポイント

```
GET /api/servers/:name/files/download?path=<filepath>
```

## 外部エディタ連携

ファイルプレビュー画面から外部エディタでファイルを直接開くことができます。

### 対応エディタ

| エディタ | ボタン | URI スキーム |
|---|---|---|
| VS Code | 「Open in VS Code」 | `vscode://` |
| Zed | 「Open in Zed」 | `zed://` |

いずれの場合も、**ファイルの親ディレクトリ**がエディタのワークスペースとして開かれます。

### Tailscale ホスト名の自動検出

リモートサーバーのファイルを外部エディタで開く場合、AZITO は Tailscale のホスト名を自動検出し、SSH リモート接続用の URI を生成します。

- VS Code: `vscode://vscode-remote/ssh-remote+<host>/<parent-dir>` 形式
- Zed: `zed://ssh/<host>/<parent-dir>` 形式

## Browser runtime（Chromium）

AZITO の CDP ブラウザ機能（タブスナップショット、エージェント操作など）を利用するには、サーバーに Chromium をインストールする必要があります。

### 前提条件

- **Linux または macOS** のみ対応（Windows は非対応）
- **Node.js v24 以上** がホストにインストールされていること（`npx` を使用するため）

### インストール手順

1. Servers → 対象サーバー → Setup タブを開く
2. 「Browser runtime (Chromium)」セクションの **Install** ボタンをクリック
3. インストールが完了するまで待つ（タイムアウト: 10分）

内部的には `npx playwright install chromium` を実行し、Hub にインストールされている Playwright のバージョンに固定された Chromium をインストールします。

### Linux での追加処理

Linux 環境では、日本語表示に必要な **Noto Sans CJK JP** フォントが自動的にインストールされます（`~/.local/share/fonts/` に配置）。フォントのインストールに失敗しても Chromium 自体のインストールは成功します（non-fatal）。

### API

```
POST /api/servers/:name/install-browser-runtime
```

レスポンス: `{ ok, chromiumVersion, fontInstalled, warning }`
