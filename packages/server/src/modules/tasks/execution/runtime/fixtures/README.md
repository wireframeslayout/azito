`claude-2.1.317-named-empty.txt`: Claude Code 2.1.317、RC の確認のペインの capture。入力済み等の派生ケースはテスト内で加工している。Codex の名前入り枠の実画面は未取得。

`claude-2.1.319-tmux-ghost.ansi` と `claude-2.1.319-tmux-same-draft-start.ansi`: Linux の Claude Code 2.1.319 を専用 tmux ソケット、一時 HOME・設定・作業ディレクトリ、`--strict-mcp-config` で起動し、二つの短い応答後に `capture-pane -p -e` で取得した未加工の 80 列画面。前者は実際の次の入力候補 `give another tip`、後者は同じ文を手入力して Home でカーソルを文頭に戻した画面。別々に取得した画面全体がバイト単位で同一で、先頭の `g` だけが反転表示される。両画面には個人情報や一時ディレクトリのパスは含まれない。候補の生成は `CLAUDE_CODE_ENABLE_PROMPT_SUGGESTION=1` を指定した。tmux の色付きテキストだけではこの二つを区別できない例であり、misao や他のバージョンについての観察ではない。

同じバージョンを一時 HOME・設定・作業ディレクトリと専用 tmux ソケットで起動して候補の設定を確認した。起動時に `CLAUDE_CODE_ENABLE_PROMPT_SUGGESTION=false` を指定した場合、初期入力と一度の応答後の入力に候補は表示されなかった。環境変数なしで起動した別のプロセスでは候補が表示された後、一時設定ファイルの `promptSuggestionEnabled` を `false` にしても、その候補は消えず、次の応答後にも新たな候補が表示された。同じ `false` 設定で新しく起動したプロセスの初期入力には候補がなかった。これは各条件の限定的な観察であり、misao や他のバージョンでの動作を保証しない。

AZITO は新たに起動する Claude Code の環境変数を `false` にしている。既存窓に継続する場合は新規プロセスを起動せず、そのプロセスの環境変数は変更しない。AZITO の外で起動した窓や既存の Claude プロセスについては、この設定だけで候補を消して安全に送信できるわけではない。候補と同じ文を入力した場合の区別と、候補がある画面での送信は未解決。

別の同様の隔離 tmux・Claude Code 2.1.319 で、実際の候補と同文を手入力して文頭にカーソルを置いた状態を比較した。候補に対する Escape、Ctrl+U、Backspace はいずれも表示を消さなかった。`x` を入力すると候補は `x` に置き換わり、下書きでは文頭に `x` が挿入された。続く Backspace ではそれぞれ候補が再表示され、下書きは元に戻った。下書きへの Escape では `Esc again to clear` が表示され、連続 Escape の後に `x` を入力すると `x` のみになった（下書きが消えた）。これはこの実験条件での観察に限る。入力を使う判別は操作の途中で他の入力や画面遷移が起きると下書きに影響しうる。Escape は操作対象の状態によって下書きの消去や実行中の処理の中断にもつながるため、自動判別には使っていない。
